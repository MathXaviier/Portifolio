O objetivo desse arquivo é explicar o processo do Desafio de Projeto da DIO: Simulando um Ataque de Brute Force de Senhas com Medusa e Kali Linux.

É importante frisar que esse projeito foi realizado em ambiente isolado e controlado, o que for descrito aqui foi utilizado unicamente para fins de conhecimento educacional.

Neste desafio foi necessário a criaçãod e duas máquinas virtuais, uma contendo o SO Kali Linux, com todas as configurações necessárias e a outra com o Metasploitable 2 para agir como sistema a ser invadido.
Além das máquinas foi utilizado uma página web com alvo: o DVWA que estava hospedado no próprio Metasploitable

De inicio após a configuração das máquinas foi preciso acessar a interface do Metasploitable uma vez utilizado o login e senha que estão descritos no próprio inicio, sendo eles msfadmin / msfadmin. Logo após foi utilizado o comando 'ip a' para localizarmos o endereço de IP, sendo ele: 192.168.56.102. Cientes dessa informação poderiamos ultilizar o Kali Linux por meio de alguns comandos para verificarmos algumas informações. 

De inicio foi enviado um comando de ping (ping -c 3 192.168.56.102) enviando 3 pings e conferindo se de fato a conbexão exisita.
Conferida a conexão existentes utilizaou-se de um comando do nMap para conferirmos portas abertas dentro da máquina alvo (nMap -sV -p 21,22,80,445,129 192.168.56.102) por se tratar de um ambiente de laboratório o comando nos retornou todas as portas listadas com o status de abertas, seus seviços e suas versões e a partir dessa informação utilizamos a porta 21 que do serviço FTP a qual logar, mas antes criamos alguns comandos para que nos fornececem sendo um deles o: echo -e "user\nmsfadmin\nadmin\nroot" > users.txt, para criar um arquivo de texto com os usuários e em seguida o: echp -e "123456\npassword\nqwerty\nmsdadmin > pass.txt, para que fosse criado o arquivo com as senhas
Realizado esses comandos partimos para a aplicação Medusa que já vem com o Kali Linux e incluimos o comando: medusa -h 192.168.56.102 -U users.txt -P pass.txt -M ftp -t 6, esse comando cruza os dados dos arquivos .txt no protocolo de rede mencionado com um número de tentativas simultâneas no IP especificado, em dada tentativa ele checa o usuario: msfadmin e a senha: msfadmin e o status muda de ACCOUNT CHECK para ACCOUNT FOUND
Testando o usuário e senha no comando: ftp 192.168.56.102, conseguimos acesso ao sistema
Também utilizamos o Medusa para testar uma senha genérica para multiplas contas, para que assim evite o sistema detectar a invasão e por consequência o bloqueio por várias tentativas em uma única conta, para desdcobrimos as contas foi preciso enumerá-las para pudesse ser possivel saber onde atacar, para isso foi usado o comando: enum4linux -a 192.168.56.102 | tee enum4_output.txt, onde analisando as linhas dentro do terminal vimos os usuários que estão ali, utilizado do conceito de criação de arquivos.txt já ditos aqui podemos utilizar um comando para conseguirmos acesso: medusa -h 192.168.56.102 -U smb.users.txt -P senhas_spray.txt -Msmbnt -t 6 -T 50, esse -T 50 seria o intervalo de tempo entre as tentativas, arquivo 'senhas_spray.txt' possui senhas consideradas padrão para que possam ser aplicadas a diversos usuários, então a ideia nessa parte é ao invés de focar em um usuário apenas, e aplicar diversas senhas, usamos poucas senhas em um número amplo de usuários.

Visto que temos como foco a segurançã dos contra invasões, com o que foi visto durante esse desafio, e que a medidas de mitigação devem ser seguidas para que dificultemos possiveis invasões, com limitações de tentativas, e após um número delas bloquear o acesso a conta. Autenticação multifator, para que se um lado for invadido ainda termos um outra camada segurança. Uma politica de conscientização do uso de Senhas Fortes, com  quantidade minima e maior complexidade para inviabilizar wordlists basicas e não menos importante acompanhamento e alertas de logs, para que possa ser possivel perceber quando há anomalias nas requisições de autenticação no sistema.
